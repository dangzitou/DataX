# OLAP 批次调参与同配置原版对照

2026-09-27。**本轮没有修改生产 Java 或插件默认参数。** 同一 fork 将批次阈值从 5 MiB 调到 20 MiB，在本地 StarRocks 样本中明显提速，同时增加内存占用。这是原有配置的调优收益，不能算作源码优化收益；原版和 fork 同用 20 MiB 的两组对照仍未达到每轮 +25%。亿级零重复、零遗漏、零字段变化仍未验收。

## 对照与结果

事先记录六组计划。每组 100 万行、双方各一次预热、五对交替 AB/BA，共 72 次真实 DataX Engine；另外四次 JFR 诊断不参与速度统计。计时覆盖整个 JVM，建表、清空和外部对账不计时。所有慢轮保留，以每一对吞吐增幅判断 +25% / +50%，中位数不代替逐轮门槛。

前四组使用完全相同的 `candidate-row-count` runtime，只改变字节阈值。后两组以未修改上游 `80ec23d` 对照 fork，双方同为 20 MiB。没有运行 CSV 的同配置上游对照。

| 比较 | 对照中位秒 | 候选中位秒 | 中位吞吐变化 | 最差配对 | 每对 +25% / +50% |
|---|---:|---:|---:|---:|---|
| SR CSV，同 fork 5→20 MiB | 6.9142 | 2.8069 | +146.33% | +137.44% | 通过 / 通过 |
| SR JSON，同 fork 5→20 MiB | 8.3568 | 3.0195 | +176.76% | +148.14% | 通过 / 通过 |
| Doris CSV，同 fork 5→20 MiB | 3.8735 | 3.1048 | +24.76% | +17.09% | 失败 / 失败 |
| Doris JSON，同 fork 5→20 MiB | 4.9516 | 3.8821 | +27.55% | +17.96% | 失败 / 失败 |
| SR JSON，原版→fork，同 20 MiB | 3.4446 | 3.1112 | +10.72% | +9.30% | 失败 / 失败 |
| Doris JSON，原版→fork，同 20 MiB | 4.2712 | 4.1722 | +2.37% | −5.62% | 失败 / 失败 |

环境：Apple M5 / 16 GiB、JDK 8u504、PG 17.11 静态源、StarRocks 4.1.4、Doris 4.1.3-rc02，均使用固定镜像摘要。具体服务端版本、镜像和构建指纹保存在原始结果中。每组新建专用 OLAP 容器，4 CPU / 4 GiB；Doris BE 内存比例 60%，FE_HEAP=1024m、BE_HEAP=512m。双方单通道、1 GiB Java 堆、队列长度 1、最大 500000 行，PG fetchSize=1024；`strict_mode=true`、`max_filter_ratio=0`。性能作业期间没有并行构建、压缩、采样或其他数据库测试；未停止其他项目的容器，仍不能排除共享机器噪声。

## 内存和提交边界的代价

下列为五个测量轮的**进程峰值 RSS 中位数**，不是 Java 堆使用量，也不含数据库容器内存。

| 同 fork 调参 | 5 MiB RSS | 20 MiB RSS | 实际上传尝试次数 |
|---|---:|---:|---|
| SR CSV | 457.42 MiB | 595.00 MiB | 60→15 |
| SR JSON | 457.81 MiB | 622.42 MiB | 73→19 |
| Doris CSV | 479.00 MiB | 988.09 MiB | 60→15 |
| Doris JSON | 487.00 MiB | 1082.77 MiB | 73→19 |

20 MiB 下 Doris JSON 单轮最高 RSS 为 1110.09 MiB。更大批次保留更多在途数据，内存不足时可能失败；不能因为速度提高就直接扩大线上批次。阈值不含全部分隔符等开销：本轮最大实际正文约 20.06 MiB，不是严格 20 MiB 请求上限。

同为 20 MiB 的 SR JSON 原版→fork，RSS 中位数为 857.69→582.14 MiB；Doris 为 1081.95→1043.44 MiB。这些是当前负载的测量，不能外推任意字段宽度和通道数。

批次改变也改变提交边界和失败时可能已提交的范围。逐次 Stream Load 成功不能证明整个 DataX 作业原子成功，批次 label 也不能代替跨作业的恢复账本。StarRocks 的返回计数、过滤率和 label 语义见[官方文档](https://docs.starrocks.io/docs/sql-reference/sql-statements/loading_unloading/STREAM_LOAD/)。插件默认值保持原样；本轮 5 MiB / 20 MiB 是实验显式值，不是默认值之间的对比。

## 正确性验收范围

72 次对照和 4 次诊断都使用会保留重复行的 Duplicate Key 表，检查行数、精确不同主键数、键范围，并由主键独立计算另外五列应有值，逐行比较 NULL、数值、时间、中文/emoji 和文本。均为 100 万行、100 万不同键、字段差异 0；不会用主键表覆盖重复写入来掩盖问题。每次运行的实际 JSON 配置也与报告逐项核对。

这只验证静态六列样本的正常传输。本轮没有新增断网、宕机、未知提交结果、在线变化源或复杂类型测试，也不是一次连续 7600 万行、亿级作业或生产错误率测量。

对于“错误数据不能进入业务表”的要求，**当前普通写入模式尚不合格**：

- 先前批次可能已提交，失败后整作业重跑仍可能重复；唯一键不能证明源数据无遗漏或字段未变。
- 源在线更新需要共同快照和固定分片覆盖。PG 的 `consistentSnapshot` 只覆盖本次作业，重跑会取得新快照；见[读取说明](../postgresqlreader/doc/postgresqlreader.md)。
- `errorLimit=0` 和零过滤率只能阻止已检测到的错误。PG 批量重写的未知计数仍有实测漏检反例，见[行数检查报告](REPORT-jdbc-row-count.zh-CN.md)。
- 实验性 `atomicBatchId` 只覆盖受限的 PG 单表追加，不覆盖 SR/Doris，不防不同批次范围重叠，未验收亿级容量；见[写入说明](../postgresqlwriter/doc/postgresqlwriter.md)。

生产验收仍需实际源/目标表定义、源更新方式和重复语义：固定源版本及范围，写入隔离暂存目标，核对缺失/额外记录、重复次数和全字段后发布；对每个故障点重复验证恢复结果。失败或结果不确定时不发布，也不盲目换 ID 重跑。不是加一个“严格模式”参数就能获得端到端保证。

## 诊断、复现和磁盘

四次单独采样均使用当前 fork、5 MiB 阈值，根日志 INFO，仅 Stream Load visitor 为 DEBUG，避免记录 HTTP 正文。StarRocks CSV/JSON 的服务端提交与发布计时累加为 3836/4661 ms；Doris 为 1226/1458 ms。它们可能与读取、编码重叠，不能相加当作作业耗时；JFR 样本也不是精确耗时占比。这些线索促成批次实验，不能单凭采样断言速度收益。

复现需要专用测试容器和百万行静态 PG 样本，会清空专用测试目标。容器启动、就绪和按 ID 清理步骤在归档 runner 中，不能指向业务数据库。例：

```sh
python3 benchmarks/olap_scenarios.py /tmp/datax-perf/candidate-row-count \
  /tmp/datax-perf/candidate-row-count /tmp/datax-perf/new-sr-json-batch \
  --backend starrocks --scenario writer-json --rounds 5 \
  --baseline-batch-mib 5 --candidate-batch-mib 20
```

脚本现在分别保存双方配置，并从真实日志记录上传尝试次数、最大正文及尝试字节数；这些不是成功提交计数。局部批次参数限制为 1–32 MiB，读取场景拒绝非默认批次覆盖。

每组结束删除本轮创建且 ID 匹配的 OLAP 容器，同时只存在一个。运行间的数据库体积检查上限为 6 GiB，并留 1 GiB 余量；不是硬配额。最高运行前检查值为 3694903296 字节，包含复用的 PG 源。未生成新百万行源。四份完整 JFR 不公开归档，保留选定采样事件、配置、日志和计时；删除已归档的临时重复事件文件和完整 JFR。

[原始证据](results/2026-09-27-olap-batch/)包含事前计划、六组 72 次结果、四次诊断、全部 76 份 Engine 日志、容器记录、运行脚本及校验摘要，约 16.2 MiB。两个 runtime 的全部 JAR 哈希重新核验。候选构建为 `baf6c1f` 加归档行数修复补丁，生产实现对应 `255d256`；本轮未重新构建或改写该 runtime。完整计时、逐轮门槛和内存结果见 `olap-batch-summary.json`，最终磁盘状态见 `storage-after.json`。
